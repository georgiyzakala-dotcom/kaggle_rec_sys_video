# Task14: полное обучение системы с профилями Task13

Запуск из корня репозитория:

```bash
./scripts/run_task14_full_fit.sh configs/task14_full_fit_v1.json
```

Результат: `artifacts/task14_full_fit_v1/submission.csv`. Файл появляется в
готовом каталоге только после успешной проверки. Формат соответствует уже
использованному Task11: `user_id,item_ids`, список целых item IDs внутри CSV.
На Kaggle runner ничего не отправляет. Прежний submission сохраняется.

## Что обучается

Зафиксирован лучший рецепт Task13 `D_all`: 221 признак, Logloss, 1,030 деревьев,
depth 7, learning_rate 0.08, 32 свежие границы квантования, без positive-weight.
Канонические метрики его **валидационной** модели:
`P20_all = 0.005077640992845437`, `P20_labeled = 0.006911912728855518`.
Против Task08 это `+0.000393781114829021` labeled (около +6.04%).

1. Для ранкера используются все четыре доступных размеченных временных фолда:
   rolling_1, rolling_2, rolling_3 и canonical. Профили для каждой обучающей
   строки пересчитываются из истории и ALS **этого фолда**. Готовые immutable
   Task06/07 кандидаты и исходные 201 признак исторических фолдов переиспользуются.
2. Новый CatBoost обучается с нуля. Сохраняется бюджет примерно 30 млн строк
   суммарно, распределённых поровну между четырьмя фолдами: все положительные
   примеры, детерминированная выборка отрицательных, веса с учётом обеих
   вероятностей сэмплирования. Это обучение на всех доступных размеченных днях,
   с выборкой отрицательных пар для соблюдения лимита RAM. Границы признаков
   определяются заново только на этой обучающей выборке.
3. Из **всех raw events всех пользователей**, включая последний день,
   создаётся новый общий daily snapshot. Старый календарный prepared train
   не используется. Горизонт предсказания начинается после последнего raw event.
4. На этом snapshot заново обучаются четыре production источника: global
   popularity, recency popularity, item2item и ALS (128 факторов, 15 итераций).
   Из прежних winner artifacts берутся только выбранные настройки.
5. Заново вычисляются user/item statistics, нормы факторов и четыре профиля
   пользователей из **нового полного ALS**. Генерируются новые кандидаты
   (до 200 от каждого источника, union до 800), после чего работает новый ранкер.

Полный ALS нельзя использовать для признаков обучающих фолдов: это открыло бы
будущее относительно их меток. Отдельного будущего дня для оценки финальной
модели нет; её две P20 в `metrics.json` равны `null`, а прежние измеренные
значения сохранены отдельно как `validation_reference`. Добавление четвёртого
фолда — финальный refit; улучшение leaderboard ещё предстоит измерить.

## Этапы, ресурсы и время

Восемь фаз: проверка фолдов и их профилей; полная daily history; sampling и
fresh quantization; CatBoost; четыре candidate fits; полные признаки и профили;
кандидаты и ranking по шардам; проверка и атомарная публикация.
Терминал показывает общий progress/ETA, фолд/модель, деревья, batches и shards.
Для непрозрачных native операций пишется heartbeat раз в 30 секунд.

Ориентир на текущей машине — **1.5–2.5 часа**, без гарантии: full Task13 занял
74.4 минуты, а здесь меньше fits ранкера, но есть полная production генерация
кандидатов. Время зависит от I/O, скорости CPU/ALS и доступной памяти.

Лимиты Task13 сохранены: 8 CPU threads, BLAS 1; CatBoost GPU 0,
`gpu_ram_part=0.70`; остановка при process-tree RSS выше 40 GiB или свободной
RAM ниже 4 GiB. Для старта требуется 38 GiB available RAM, 13,000 MiB свободной
VRAM, 110 GiB свободного Linux-диска и 160 GiB на G:. Аварийные минимумы:
2,048 MiB VRAM, 15 GiB Linux, 50 GiB G:. Проверки работают каждые 2 секунды
отдельным процессом, в том числе во время native CatBoost calls.

По Task13 ожидается около 32 GiB peak RSS на обучении; четвёртый фолд не
увеличивает общий бюджет строк. Полная feature matrix для всех пользователей
не хранится: рекомендации считаются по 2,048 пользователей, после завершения
шарда остаются его top-20 и диагностика. Оценка временного прироста диска
60–100 GiB; пиковый TSV ограничен 60 GiB и удаляется после квантования.
Уже имеющиеся Task13 work caches в эту оценку прироста не входят.

## Контроль, остановка и продолжение

```bash
tail -f logs/task14_full_fit_v1.log
cat logs/task14_full_fit_v1.resources.json
nvidia-smi
df -h . /mnt/g
```

Остановить: `Ctrl-C` в терминале launcher либо из другого терминала:

```bash
kill -TERM "$(cat logs/task14_full_fit_v1.pid)"
```

Для продолжения повторить исходную команду с тем же config. Сохраняются
atomic checkpoints после каждого фолда, candidate fit и inference shard;
CatBoost также сохраняет snapshots. Незавершённая операция повторяется,
завершённые проверяются и пропускаются. Config и код защищены SHA256:
не редактировать их посреди расчёта. Дублирующий запуск блокируется lock.

Если расчёт закончен, но прервана финальная проверка/публикация полностью
подготовленного artifact:

```bash
./scripts/run_task14_full_fit.sh configs/task14_full_fit_v1.json --publish-only
```

Этот режим не вызывает обучение или генерацию рекомендаций. Если готовый
каталог уже существует, проверить его отдельно:

```bash
OMP_NUM_THREADS=8 OPENBLAS_NUM_THREADS=1 POLARS_MAX_THREADS=8 \
  .venv/bin/python scripts/run_profile_full_fit.py \
  --verify-only artifacts/task14_full_fit_v1
```

Проверяются checksums, все target IDs и ровно 20 уникальных известных unseen
items на пользователя, отсутствие null, точный CSV round-trip, обучение всех
источников на одном полном snapshot, связь профилей с новым ALS и повторный
portable prediction. Во время полного inference повторяются scores каждого
шарда из второй загрузки сохранённого CatBoost. Повторное обучение на GPU
может отличаться численно даже при том же seed.

Логи ограничены ротацией. Checkpoint и временные данные:
`artifacts/.task14_full_fit_v1.work/`. Не удалять их до проверки результата.
Для финального artifact сохраняются ranker, все четыре source models,
history, profiles, lookups, borders, training/sampling provenance и CSV.

## Быстрая проверка кода

```bash
.venv/bin/python scripts/run_profile_full_fit.py --help
bash -n scripts/run_task14_full_fit.sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=2 POLARS_MAX_THREADS=2 \
  .venv/bin/python -m unittest discover -s tests -q
./scripts/run_task14_full_fit.sh configs/task14_full_fit_smoke_v1.json
```

Smoke ограничен 64 пользователями, четырьмя первыми Task07 shards и 12
деревьями CPU. Все production модели в нём тоже обучаются заново на его
ограниченной истории. Его CSV не предназначен для отправки на соревнование.
Результаты можно открыть через `research/14_full_fit_history_profiles.ipynb`.
